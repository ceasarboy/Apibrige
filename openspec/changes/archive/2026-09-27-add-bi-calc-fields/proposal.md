# add-bi-calc-fields 提案

## Why

生产运行管理看板验收后，用户提出下一步需求：**表格数据的聚合与字段转换计算**。
现状的硬缺口（做看板时被真实绊到）：

1. **派生列算不出来**：真实业务表通常不存"比率"列——合格率 = 合格数 / 检验数、
   达成率 = 实际 / 计划、单位成本 = 金额 / 数量。当前只能展示源表已有列；
   生产测试库的 `pass_rate/attain_rate` 是**造数时预计算好的**（真实表没有），
   再往前一步（如"整体达成率 = Σ实际/Σ计划"、"不良率 = 不良/检验"）完全无法配置。
2. **离散值不能归类**：产线/区域/客户等级这类维度常有长尾取值，看板需要
   "自定义分组"（如把若干产线归为"一车间/二车间"、其余归"其他"）。
3. **展示层的派生口径缺失**：占比（当前占比）、累计（累计趋势）这类展示型
   计算当前没有。

设计参照 DataEase v3 源码（本轮已调研并核实）：

- **计算字段**（`CalcFieldEdit.vue` + `Utils.buildCalcField` + `Field2SQLObj`）：
  表达式以 `[字段]` 引用（存字段 ID）、**递归解析**（计算字段可引用计算字段，
  深度上限 100，循环引用报错）、**参数替换**（`[参数名]`→值）、
  **占位符注入**（`CALC_FIELD_PLACEHOLDER` 先占位、SQL 方言转换后替换）、
  函数面板 11 个内置（SUBSTRING/ABS/CEIL/FLOOR/ROUND×2/聚合 5，按类型分组
  0文本/1时间/2数值/3逻辑/4聚合）、含聚合函数的列不做枚举值预览
- **字段扩展三型**（`ExtFieldConstant`）：EXT_COPY 复制字段 / EXT_CALC 计算字段 /
  **EXT_GROUP 自定义分组**（`groupList` 值→组映射 + `otherGroup` 其余归组，
  转 CASE WHEN）
- **快速计算**（图表层指标属性，`QuotaItem.quickCalc`）：占比 percent（自动设
  百分比 2 位小数）/ 累计 accumulate / 同环比五类（日环比、月同比、年同比、
  月环比、年环比；`YoyChartHandler` 把过滤器时间回调一年取数再计算剔除）

## What Changes

按本项目架构（form 源快照 + Python 内存聚合引擎，**非 SQL 下发给源库**）落地等价能力：

1. **派生列（行级计算字段）**：指标定义新增 `computed: [{key, name, expr, field_type}]`——
   对被拉取的行逐行求值生成新列，供 dimensions/measures 引用。
   表达式语法 `[字段名]` 引用行键 + 四则运算 + 括号 + 函数子集
   （`round/abs/ceil/floor/min/max/coalesce`，数值域起步）；引用关系递归解析、防循环。
2. **聚合比（度量级表达式）**：measures[] 的 agg 扩展 `ratio`——`{key, agg:"ratio",
   numerator:{field, agg}, denominator:{field, agg}, scale?}`（如整体达成率 =
   `sum(实际)/sum(计划)`）；分母为 0 或空时报 null（不编造）。
   （区分：行级派生列 + avg = 平均比率；聚合比 = 比率的整体值，两种口径都保留）
3. **自定义分组（维度值归类）**：dimensions[] 扩展 `groups: [{name, values[]}]` +
   `other: "其他"`——聚合前把维度值按映射归一（未命中归 other）。
4. **展示层派生（轻量，评估后定）**：饼图/柱状占比（%）与序列累计（cumsum）——
   在转换层（bi_format）加修饰开关，不动聚合语义。
5. **不做（明确排除）**：同环比（快照源无业务时间轴、取不到"去年同期"——buffer/logs
   滚动源理论上可做，本轮不做，记 backlog）；维度/指标转换（本项目字段分类由
   bi_type 固定，无切换需求）。

## 拍板点（请用户确认）

- **P1 表达式语法**：`[字段精确名或中文显示名]` 二选一还是都支持？
  （建议：优先中文显示名，回落字段 path——对操作员更友好）
- **P2 函数集起点**：`round/abs/ceil/floor/min/max/coalesce` 够用吗？
  （建议起步这 7 个，字符串/日期函数后续按需加）
- **P3 聚合比语法**：度量内嵌 `numerator/denominator` 对象（建议）还是
  复用 expr 表达式（`sum([合格])/sum([检验])`，更灵活但与函数集耦合）？
- **P4 展示层占比/累计**：本轮一起做还是只做 1-3（数据准备层）？
  （建议：本轮一起做，工作量小且看板立刻受益）

## Impact

- **specs**：`bi-aggregation` 预计新增 3-4 组需求（派生列 / 聚合比 / 自定义分组 /
  展示层派生），修改「聚合定义配置化」与「图表格式转换契约」
- **代码**：`app/services/bi_defs.py`（定义校验 + 表达式解析器新模块）、
  `bi_aggregator.py`（行级求值 + 分组归一 + ratio 算子）、`bi_format.py`（占比/累计）、
  `app/api/bi.py`（定义 CRUD 无需大改，schema 透传）
- **前端**：定义页「计算字段」编辑器（表达式输入 + 字段/函数插入辅助）、
  维度分组配置弹层（值列表 → 组映射）
- **兼容**：现有定义零影响（新键可选）；快照源语义不变（派生在行上做，聚合照旧）
- **不做**：同环比（快照源限制，backlog）、维度/指标转换
