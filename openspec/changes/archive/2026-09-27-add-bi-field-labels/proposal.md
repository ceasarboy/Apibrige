# add-bi-field-labels 提案

## Why

用户反馈（2026-09-27）："少了 BI 一个重要的功能——显示字段的名字需要调整，比如实际是
`work_date`，我可能设置为'生产时间'"。

现状：明细表头显示字段名 = 字段字典 name（连接级，若配置过）否则原始列名（`work_date`
这类英文列名直接上屏，大屏给业务人员看时不可读）。连接级字段字典（ConnectionField）
机制已存在且 `/bi/form-fields` 已合并其 name——但入口在「字段字典」页（全局、按连接），
**BI 卡片级没有便捷的列名设置**：同一份数据在不同看板需要不同叫法时无法表达，
且配置动线割裂（建看板要跳去字段字典页）。

## What Changes

1. **卡级列显示别名**：指标定义 `style.column_labels`（自由 JSON，零迁移）——
   `{"work_date": "生产时间", "actual_qty": "实际产量"}`。
2. **明细表头与排序下拉**显示名优先级：**卡级别名 > 字段字典 name > 原始字段名**。
3. **定义页入口**：明细图表的定义编辑页新增「列显示名」区（列出表单字段，
   逐行输入别名；留空回落默认）。
4. 全局改名仍走字段字典（既有机制，文档说明两者差别与优先级）。

## Impact

- **specs**：`bi-aggregation` 新增 1 组需求（字段显示别名）
- **前端**：`BiBoard.tsx`（DetailTable 表头映射）+ `definitions.tsx`（列显示名编辑区）
- **后端**：零改动（style 自由 JSON 透传；无新校验）
- **不做**：图表卡的维度/度量显示名（`dimensions[].name` / `measures[].label` 已可自定义）；
  行级/列级权限（P6 另立）
